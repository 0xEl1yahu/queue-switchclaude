# M4 Daily-Use Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every small item the M1 to M3 reviews and acceptance runs left open, re-verify the last fixes live, and ship 0.4.0 as the build Eli runs in daily sessions with Shadow compare on, so real usage data decides what comes next.

**Architecture:** No new subsystems. Intake's pass-through outputs gain a visible `systemMessage`; the hook scripts measure their own start-up; garbage collection also prunes stale pointers; descriptions, docstrings, README and a new CHANGELOG are brought in line with the code; a short live run covers the four most recent fixes.

**Tech Stack:** Python 3.10+ stdlib under `scripts/`, `pytest`, Claude Code plugin manifests.

**Spec:** `docs/design-spec.md` §10 M3 ("whatever usage logs show"); the open-item list in the session's wrap-up of 2026-10-19; `docs/m3-acceptance.md` observations; the M3 review nits.

## Global Constraints

- Stdlib only under `scripts/`; hook scripts exit 0 silently on any error; no change to hook output shapes beyond adding `systemMessage`, and no change to `classify.SCHEMA` or the golden set. The cached eval gate stays at 44 of 47.
- A `systemMessage` is at most one line; it never repeats text Claude already prints.
- Version `0.4.0` in `.claude-plugin/plugin.json`; `marketplace.json` and `plugin.json` carry the same description string.
- Store files from M0 to M3 keep loading.

## Review Focus

1. A `systemMessage` added to a pass-through must not change what Claude reads: `additionalContext` stays byte-identical. Test in Task 1.
2. `hook_ms` must never be negative or absurd when the start stamp is missing (events built by hand, or a script started another way): it falls back to the parse-time clock. Test in Task 2.
3. Pointer cleanup must never delete the pointer of a live session, even when its store file has not been written yet (a session whose first message was a pass-through). Test in Task 3.
4. The README install section must match what the UI actually shows (scope picker, options screen, the uninstall panel), as recorded in `docs/m3-acceptance.md` scenario W. Checked by reading in Task 4.
5. The live re-run must use the driver's input-clearing send, or the held-text concatenation of the first Q attempt in `docs/m2-fixes-acceptance.md` recurs. Task 5 says so.

- Every pass-through that tells Claude something the user should also know passes `show`:

| Path | `additionalContext` (unchanged) | `systemMessage` |
|---|---|---|
| idle `later: x` runs now | `…nothing is running, so this starts now: x` | `queue-switchclaude: nothing was queued, running now: x` |
| Esc dropped queued tasks | `…the previous turn was interrupted, dropped queued tasks: p2 (…)` | `queue-switchclaude: Esc dropped p2, p3` |
| Esc during planning | `…the planning turn for p2 was interrupted; it is queued again` | `queue-switchclaude: p2 is queued again` |
| split, steer part through | `…handled the rest of this message: queued p2 …; act only on: …` | `queue-switchclaude: queued p2 after p1: …` (the confirmations only) |
| approval (`lgtm`, `continue`, `queue: approve`) | the execution handover | `queue-switchclaude: running p2` |
| revise | the revise handover | `queue-switchclaude: revising the plan for p2` |
| confirmation closes a task | the next planning handover, when any | `queue-switchclaude: p2 confirmed done` |
| answer resumes a task | none | none (nothing to say) |

### Task 2: Honest hook latency

**Files:**
- Modify: `scripts/intake.py`, `scripts/dispatch.py`, `scripts/interrupt.py`, `scripts/queue_cli.py`, `scripts/qsc/hookio.py`, `eval/shadow_report.py`

**Interfaces:**
- Produces: each entry script's first statement after its module docstring (and after a `from __future__` import where one exists, which Python requires to come first) is `import time; _T0 = time.monotonic()`; it passes `_T0` to `hookio.read_event(expected, started=_T0)`.
- Produces: `hookio.read_event(expected, started: float | None = None)` stores `event["_hook_started"] = started` when given, else the parse-time clock as today. `hookio.start_clock(event)` is unchanged.

- Produces: `eval/shadow_report.py` prints a line `python3 start-up: N ms (median of 5 runs of python3 -c pass)` measured at report time, and a sentence that `hook_ms` excludes it; the p50/p95 lines are unchanged.
