# M2 Plan Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every queued task is planned just in time from the previous task's handoff, shown to the user for approval before it runs, and judged done by a verify command or a model judge instead of "Claude stopped".

**Architecture:** The main session's own Claude writes each plan and executes it; the harness only steers it through Stop-hook handovers and a small state machine (`idle`, `running`, `planning`, `awaiting_approval`, `awaiting_answer`). Dispatch gains three stages on every Stop: close the running task (verify command, else a haiku judge via `claude -p`), write its handoff, then either ask for a plan, record a plan, re-plan a stale one, or hand an approved plan over. Intake learns the two waiting states so "lgtm", "looks good but X first" and a plain answer route correctly. One new generic model caller (`qsc/model.py`) serves the classifier and the judge.

**Tech Stack:** Python 3.10+ stdlib only under `scripts/`, `pytest`, `claude -p` for the classifier and the judge, Claude Code plugin hooks (Stop timeout raised).

**Spec:** `docs/design-spec.md` sections 3 (state table), 4.3, 6, 7, 10 (M2), 11; `docs/decisions.md` D3, D4; golden cases g44 to g47 (context E).

## Global Constraints

- Everything under `scripts/` is Python 3.10+ stdlib only. Hook scripts exit 0 with empty stdout on any error. New branches fail open: an unreadable plan, a judge failure or a verify timeout never strands the session; the fallback in each case is named in the task.
- Plans and handoffs live under the plugin data directory, not the user's repository: `paths.plan_path(session_id, task_id)` = `data_dir()/sessions/<sid>/plans/<task_id>.md`, `paths.handoff_path(...)` = `.../handoffs/<task_id>.md`. Spec §4.3 wrote `plans/pN.md`; the user's working tree stays clean (deviation recorded in Task 2).
- Handover text to Claude always starts with `queue-switchclaude:` and names the task id and the absolute file path it must read or write.
- The judge call uses the same isolation flags as the classifier: `claude -p --model haiku --setting-sources "" --strict-mcp-config --tools "" --output-format json --json-schema <schema> --system-prompt <prompt> <payload>`, 15 s timeout. The judge is conservative: `done` only when the closing message says the work is complete; a question to the user is `asked_question`; anything else `not_done`.
- A verify command runs with `subprocess.run(cmd, shell=True, cwd=event["cwd"], timeout=120)`; exit 0 means done. `hooks/hooks.json` Stop timeout becomes 180 s.
- Continuations are bounded: a task gets at most 2 "not done, continue" handbacks (`Task.attempts`), then it is marked `done` with `verdict: "gave_up"` logged, so the Stop-hook continuation cap (8) is never reached by us.
- Store files written by M1 load unchanged; new fields have defaults.
- Store state strings: `idle`, `running`, `planning`, `awaiting_approval`, `awaiting_answer`. Task statuses add `planned` and `failed_verify`. `Store.ready()` is unchanged.

## Review Focus

1. The user types an unrelated new task while a plan is awaiting approval: it must run as a normal turn, and the planned task must be re-presented for approval after that turn, not lost and not silently executed. Test in Task 6 and Task 5.
2. Claude stops during a planning turn without writing the plan file (asked a question, hit an error): dispatch must not loop; after 2 attempts the task returns to `queued` with a log line and the user is told. Test in Task 5.
3. A verify command that hangs: the Stop hook must return within its timeout with the task marked `failed_verify` and the output tail handed back, never leaving the store locked or the task `running` forever. Test in Task 4.
4. "ok" typed while a plan awaits approval is an approval; "ok" typed while idle is still a non-task pass-through. The `non_task` short-circuit must not run before the state check. Test in Task 6.
5. A task marked `auto` skips the gate but still gets a plan and a handoff; its planning turn flows straight into execution in one handover. Test in Task 5.

**Files:**

**Interfaces:**
- Produces: `done.VERDICTS = ("verify_ok", "verify_failed", "done", "not_done", "asked_question", "gave_up", "stopped")`.
- Produces: `done.Verdict` dataclass: `verdict: str`, `reason: str`, `output_tail: str = ""`.
- Produces: `done.run_verify(command: str, cwd: str | None, timeout: float = 120.0) -> Verdict`: `verify_ok` on exit 0, else `verify_failed` with `reason = "exit {code}"` and the last 1500 characters of combined stdout+stderr in `output_tail`; a `TimeoutExpired` gives `verify_failed` with reason `timeout after 120 s`.
- Produces: `done.JUDGE_SCHEMA`: object `{verdict: enum(done, not_done, asked_question), confidence: number, reason: string}`, all required, no extras.
- Produces: `done.judge(task_text: str, notes: list[str], plan_excerpt: str, closing: str, claude: str = "claude") -> Verdict`: `model.call(JUDGE_PROMPT, JUDGE_SCHEMA, payload)`; maps to `Verdict(verdict, reason)`; on `None` returns `Verdict("done", "judge unavailable; fail open")` (fail open means the queue keeps moving; the log carries `judge: null`). `not_done` with confidence below 0.7 is treated as `done` (conservative in the direction of not nagging).
- Produces: `done.decide(task: store.Task, event: dict, plan_excerpt: str, claude: str = "claude") -> Verdict`: `run_verify` when `task.verify` is set, else `judge` with `event["last_assistant_message"]`; an empty closing message is `Verdict("stopped", "no closing message")` which counts as done.
- `prompts/judge_system.md`: the judge's job in one paragraph; the three verdicts defined; "done means the closing message states the task's work is complete and names what was produced; asked_question means it ends by asking the user something it needs answered; otherwise not_done; when unsure between done and not_done, answer done with low confidence"; input fields; "Answer with JSON only."

### Task 5: Dispatch v3, the plan-flow state machine

**Files:**
- Modify: `scripts/qsc/dispatch.py`
- Modify: `hooks/hooks.json` (Stop timeout 180)
- Test: `tests/test_dispatch.py` (append; existing tests keep passing except where noted)

**Interfaces:**
- Consumes: `done.decide`, `paths.plan_path/handoff_path`, `store` v3.
- Produces: `dispatch.handle(event, shadow=False, claude="claude") -> dict | None`. Behaviour by `s.state` on Stop:

**A. `running`** (a task was executing):
1. Interrupt flag and `paused` handling as in M1.
2. `verdict = done.decide(running, event, plan_excerpt)` where `plan_excerpt` is the first 1500 characters of the plan file if it exists.
3. `verify_failed` and `running.attempts < 2`: `attempts += 1`, status stays `running`, return handback `queue-switchclaude: task {id} failed its verify command ({reason}). Output tail: {tail}. Fix it, then stop.` Log `dispatch` with `verdict`.
4. `not_done` and `attempts < 2`: `attempts += 1`, return handback `queue-switchclaude: task {id} does not look finished: {reason}. Finish it, then stop.`
5. `asked_question`: status stays `running`, `s.state = "awaiting_answer"`, `s.pending_task = id`, return `None` (the turn ends; the user answers).
6. Otherwise (`verify_ok`, `done`, `stopped`, `gave_up` when attempts exhausted): `write_handoff(s, running, verdict)` with `closing = last_assistant_message`; the file is `# Handoff {id}\n\n## Task\n{text}\n\n## Notes\n- …\n\n## Verdict\n{verdict}: {reason}\n\n## Closing message\n{closing}`. Then continue to **D**.

**B. `planning`** (Claude was asked to write a plan for `pending_task`):
1. If `plan_path` exists and is non-empty: task `status = "planned"`, `plan_based_on = s.done_ids()`, `attempts = 0`. If `task.auto`: hand over for execution (**E**). Else `s.state = "awaiting_approval"`, return `None`: the plan Claude just presented is on screen and the turn ends. Log `dispatch` with `planned=id`.
2. Else `attempts += 1`; if `attempts < 2` return the planning handover again; else `status = "queued"`, `attempts = 0`, `s.state = "idle"`, `s.pending_task = None`, log `plan_failed`, return `None`. (Review focus 2.)

**C. `awaiting_approval` or `awaiting_answer`**: a Stop in these states means the user's turn ran something else (Task 6 made it a normal turn and set `state = "running"` for that turn, so this case is only reached when nothing changed). Return `None`.

**D. Choosing what is next** (reached after a task closes, or from `idle`):
1. `s.state = "idle"`, `s.running_task = None`, `s.pending_task = None`.
2. Re-plan stale children: for each `t in s.stale_planned()`: `t.status = "queued"`, delete its plan file, log `replan`.
3. If `s.paused` or shadow mode: as in M1 (shadow reports the would-be task).
4. `ready = s.ready()`; a task with status `planned` and all deps done counts first: if any `planned` task is ready-equivalent (status `planned`, deps done) and `s.state` was not `awaiting_approval`, re-present it: `s.state = "awaiting_approval"`, `s.pending_task = id`, return handback `queue-switchclaude: task {id} is planned at {plan_path} and waiting for your approval; present the plan briefly and stop.` (Review focus 1.)
5. Else take `ready[0]`: spin guard as in M1; then **planning handover**: `status` stays `queued`, `s.state = "planning"`, `s.pending_task = id`, `s.last_dispatched = id`, return `queue-switchclaude: next task is {id}: {text}{notes}. Read the handoff of what came before at {handoff paths of its depends_on that exist, comma separated, or "none"}. Write a short plan for {id} to {plan_path} (goal, steps, how to verify), present it to the user in a few lines, then stop and wait for approval.` For an `auto` task the last sentence is `…then carry it out immediately without waiting.` and state is still `planning` (stage B handles the file check and hands execution over).

**E. Execution handover** (from B for auto tasks, and from intake's approval in Task 6 which calls `dispatch.start(s, task) -> dict`): `status = "running"`, `s.running_task = id`, `s.state = "running"`, `s.pending_task = None`; the text is `queue-switchclaude: task {id} is approved. Execute the plan at {plan_path} now. When it is done, say what was produced and stop.`

Produces: `dispatch.choose_next(s: store.Store) -> str | None`: stage D as a function returning the handover text (planning, re-present, or `None`), used by `handle` and by intake's confirmation branch. Produces: `dispatch.start(s: store.Store, task: store.Task) -> str`: applies the execution transition and returns the handover text; dispatch wraps it with `dispatch.handback(text) -> dict` (the Stop `additionalContext` envelope, replacing `_handoff`), intake wraps it with its own `_context(text)`. Produces: `dispatch.write_handoff(s: store.Store, task: store.Task, verdict: done.Verdict) -> Path`: sets `status = "done"`, `closing`, `verdict`, writes the handoff file, returns its path; stage A6 calls it, and so does intake when the user confirms a task done (Task 6).
